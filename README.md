# 每天领赛博鸡蛋 · daily-saibo-egg

> 一代人有一代人的鸡蛋要领。

一个自动清点 AI 免费额度的 Agent Skill：每天跑一遍，输出一份「今天能领什么、怎么领、什么时候过期、还剩几天」的清单。

覆盖四类目标：

| 类别 | 具体内容 |
|---|---|
| 文本模型额度 | 永久免费模型、新用户赠送 token、限时免费模型 |
| Agent / Coding 工具额度 | AI 编程工具、桌面 Agent 的赠送积分与限时折扣 |
| 视频 / 生图模型 | 每日免费生成次数、试用期、积分返还活动 |
| 认证类福利 | 学生认证、教师认证、开发者认证赠送的会员或积分 |

---

## 它解决什么问题

AI 圈的免费额度有几个共同特征：

- **散**——一个平台至少三条渠道。官网首页只发新闻，真正的额度条款在定价页或额度说明页；国内厂商的活动常常只在开发者社区或小程序里公示；境外厂商则优先发在官方 Blog 和 X 上。
- **变得快**——限时活动可能只挂三五天；试用期从三个月改到 30 天不会发公告。
- **不好核**——搜索引擎里能搜到大量「AI 福利大全」，但会过时，还会串行错位（把 A 厂商的活动写到 B 厂商名下）。

人工盯不住，所以交给定时任务。

---

## 产出长什么样

每条信息必须填齐四项，填不齐就不写进清单：

1. **额度**——具体是多少（3 万 token／1000 积分／每月 100 万次调用），不允许写「大量」「丰厚」；
2. **领取条件**——要不要实名、绑卡、学生或教师认证、是否限新用户；
3. **截止日期**——写年月日；**查不到就写「未标明」，绝不推算、绝不编造**；
4. **信源链接**——官方页面优先，并标注信源级别。

清单按**紧迫度**分组，不按厂商分组——使用者最怕的是错过截止日期：

```
1. 今天就到期        （红色警示，放最前）
2. 本周内到期        （按日期升序）
3. 本月内到期
4. 长期有效／永久免费 （压轴，不用着急）
```

单条格式：

```
某 Coding 工具夜间额度加成
额度：23:00—9:00 期间指定模型额度归零、其他 Agent 翻倍
条件：注册即用，无需认证
截止：2026年9月20日（还剩 1 天）
信源：<官方链接>（甲级）
```

交付两份：**Markdown** 便于复制与再编辑，**单文件 HTML** 便于直接阅读——手机打开即读，并按标题关键词自动配色配图标（到期红色、无条件绿色、认证琥珀色、永久免费蓝色）。

需要的话，还可以**直接推到手机上**：内置钉钉、飞书、企业微信、Server酱、PushPlus、Bark、ntfy 与邮件八类通道，配哪个推哪个。详见 [推送通道](#推送通道可选)。

## 核心设计

### 一、信源分四层，不以聚合站为主干

| 层级 | 内容 | 定位 |
|---|---|---|
| 第一层 · 官方直连 | 逐个平台的官网与开放平台（**先盯定价页，不是首页**） | 主干 |
| 第二层 · 官方发布渠道 | 定价页／更新日志／News／开发者社区／GitHub／公众号／X／小程序／邮件订阅 | 额度变化的真正首发地 |
| 第三层 · 聚合与社区 | 汇总仓库、免费额度专门站、价格对比站、国内科技媒体 | **只作线索** |
| 第四层 · 变更哨兵 | 抓取＋与上次快照比对，只报变化 | 「第一时间」的关键机制 |

聚合站与社区**只作线索**：任何条目回到官方页面核实之后才写入清单，核不上的标注「待确认」。

### 二、变更哨兵：为每类站点单独设计指纹

每天重读上百个网页是行不通的——又慢，还会漏掉改版后的页面。可行做法是抓一次、与上次快照比对、**只报有变化的目标**。

难点在「什么才算真变化」。报「正文从 4918 字符变成 4897 字符」是没法行动的噪声；报「新增了哪几个模型」「价格档位从两个变成三个」才是有用的信号。

| 类型 | 指纹算法 | 为什么这么设计 |
|---|---|---|
| `price` 定价页 | 只取「**价格数字集合 + 档位名集合**」 | 定价页普遍含 A/B 测试，**全文指纹必然误报**；价格集合才反映真实政策 |
| `names` 表格型站点 | 只取**第一列名称集合** | 表格站每天新增行，全文指纹只会报字符数变化；名称集合能直接说出「上架了哪几个模型」 |
| `page` 普通页面 | 全文去噪指纹 ＋ **相似度容差**（Jaccard ≥ 0.85 判为抖动） | 抹除构建 ID、nonce、时间戳，再吸掉轮播与随机推荐造成的假变化 |
| `rss` 订阅源 | 条目标识列表 | 只看有没有新条目，并直接列出新增标题 |
| `gh` 仓库 | **只取 `pushed_at`** | 星数每天微增，纳入指纹会天天误报 |
| `json` 接口 | **排序后**的条目标识 | 顺序变化（如热门榜重排）不算内容变化 |

两项保命机制：

- **跨天失败计数**——单次抓取失败是常态，连续 3 次失败才升入「疑似失效」并在报告单列。抓取失败时**不覆盖旧快照**，下一期仍能正常比对。
- **噪声源移出，而非调阈值硬扛**——站点对同一 URL 做 A/B 测试且两个变体结构不同时，任何指纹都会交替报警，属结构性噪声，只能移出；内容与「免费额度」无关的高频变化源（如服务状态页）同样移出，否则会淹没真信号。

### 三、境外不通，不等于拿不到消息

以中国大陆网络为出口时，境外平台约半数直连不通（Google 全系、Mistral、HuggingFace、xAI、Meta、Perplexity 等），部分返回 403。

但消息并非拿不到。按可靠性排序的五条绕行通道：

| 通道 | 覆盖 | 实测 |
|---|---|---|
| **镜像站替代** | HuggingFace → `hf-mirror.com`（模型 API／博客／论文／趋势／定价全套）；GitHub raw → 多个加速镜像轮换 | 取回字节数与源站**完全一致**，内容未篡改 |
| **官方 RSS 旁路** | OpenAI News、DeepMind Blog、GitHub Blog、OpenAI Status、Anthropic News、Stability News | **官网 403 或不通，RSS 照通** |
| **国内媒体搬运** | 量子位、IT之家、爱范儿、InfoQ、开源中国、少数派等 | 主站全部可达，**时效性最好的一路** |
| **免费额度／价格专门站** | `freellm.net`（30 家 provider 逐家一页）、`llm-price.com`（含上架时间） | 境外主体，但可直连 |
| **搜索兜底** | 全部境外平台，含完全不通的域名 | 实测可取回官方定价页的完整中文口径 |

值得单说的一点：`github.com` 的主站网页与 `api.github.com`、`raw.githubusercontent.com` 是三种不同状态——**网页偶发超时，API 与 raw 畅通**。按「网页打不开」就整站放弃，会把可用通道白白封死。

## 快速开始

**要求**：Python 3.8+，**无第三方依赖**（纯标准库）。

### 1. 安装

把整个目录放进 Agent 客户端的 skills 目录（遵循 `SKILL.md` 约定的客户端均可加载）：

```bash
git clone <本仓库地址> ~/.workbuddy/skills/daily-saibo-egg
```

### 2. 单次运行

```bash
cd ~/.workbuddy/skills/daily-saibo-egg

# 一步跑完前三步（省得记命令）
python scripts/run_all.py <数据目录>

# 或者逐步来：
python scripts/fetch_tiers.py    <数据目录>   # 1. 永久免费层硬数据
python scripts/fetch_overseas.py <数据目录>   # 2. 境外信源（走绕行通道）
python scripts/watch_changes.py  <数据目录>   # 3. 哨兵：只报有变化的目标
#    4. 搜索时效性活动（近 7 天过滤，六组关键词，见 SKILL.md 第四节）
#    5. 汇总成清单（四项必查，按紧迫度分组）
python scripts/render_html.py    <清单.md> <输出目录>   # 6. 渲染 HTML
```

`run_all.py` 只是把上面三条按顺序串起来，**不改变任何一个脚本的行为**——单独跑任意一条，效果与经它串联完全一致。它有几个开关：`--check` 只做环境自检（不联网）、`--init` 顺带建基线、`--html <清单.md>` 顺带渲染、`--push <配置.json>` 顺带推送。某趟失败不会中断后续，末尾统一汇总各趟退出码。

**首次运行不需要任何额外准备**：哨兵脚本自己就区分「首次建立基线」与「发生变化」，第一次跑的结果全部归入「首次建立基线（下期起可比对）」，**不会把目标误报成新增**。`--init` 是可选动作，只在「想先把基线铺好、当天不看变更」时用。

**想让哨兵盯自己的目标**：在数据目录放一份 `targets_user.json`（先跑 `--init-user` 生成带注释的样例），`add` 里加自己的目标、`disable` 里填要停用的内置目标名或网址。不建这个文件就用内置的 32 个目标，行为不变；写法有误会逐条提示并跳过，不会中断整轮。改完用 `--list-targets` 可以确认是否已生效（只列清单、不抓取）。

前三步完全由脚本完成，**不需要模型参与**——快且免费。第四步的搜索、第五步的核实与撰写才需要模型介入。把确定性工作交给脚本、把判断工作交给模型，是这条产线省成本的关键。

### 3. 推到手机上（可选）

清单落盘之后，可再推一份到手机。八类通道各自独立，配哪个推哪个：

```bash
python scripts/push_report.py --init                                     # 生成配置样例
# 编辑 push_config.json，把要用的通道 enabled 改为 true 并填好凭据
python scripts/push_report.py --config push_config.json --probe           # 通道自检
python scripts/push_report.py --config push_config.json --report out/最新一期.md
python scripts/push_report.py --config push_config.json --report out/最新一期.md --dry-run  # 只预演
```

**零配置起步用 [ntfy](https://ntfy.sh)**：不需要注册、不需要任何凭据，自取一个不易撞名的主题名填进配置，手机装 ntfy 应用订阅同名主题即可收到。这是八条通道里唯一开箱即用的一条。

不配置推送不影响任何主流程——清单照常产出与归档。

### 4. 挂定时任务

每天固定时间跑一次即可。注意：**机器需处于开机状态，否则该次不执行**。

## 已知限制

- **不做登录态操作**。所有抓取只针对公开页面与免密钥接口，不涉及账号登录。
- **搜索环节依赖 Agent 客户端提供的搜索能力**，请勿自行抓取搜索引擎结果页（实测某引擎结果页 HTML 结构已变，解析出 0 条）。
- **`RSSHub 能把任意网站变 RSS` 是误解**：实测 29 条常用路由仅 4 条可用，其余大量 503，只作补充通道。
- **视频与生图平台的官网多数抓不到可用信号**。2026-09-20 对 16 个站点逐站实测：一半是 SPA 壳页（正文仅 4–83 字）或域名不可达；另有即梦／可灵／海螺这类「正文够长、连抓 3 次零波动，但既无价格也无档位名」的——拿来做指纹只会报改版，反映不出额度变化，故不收。**哨兵里这类平台只留了 2 个目标**（MiniMax 开放平台、Flux 官方定价），其余走搜索兜底。判一个站能不能进哨兵：先看有无价格或档位这类结构化信号，再看稳不稳定，两条都过才收。
- **部分站点对爬虫限流严格**，脚本内已压低并发并加重试；请勿提高并发，否则会被整体限流。
- **活动规则以官方页面为准**。本产线只做聚合与核实，不替任何厂商作宣传。

## 红线

1. 不编造额度和日期。查不到截止日期就写「未标明」。
2. 不把「可能」「听说」写成既定事实。未核实内容明确标注「待确认」。
3. 不写需要绕过风控或违反平台条款的「薅法」，只写官方渠道的正当领取方式。
4. 数量不作目标：宁可写 5 条准确的，不写 20 条含水的。搜不到新内容时如实写「本期无新增」。
5. 有身份门槛的福利写清门槛，但不替使用者下结论。
6. 国内政府网站与 UGC 平台不作信源。
7. **不代使用者领取额度。** 不做代登录、不代为提交认证材料、不代为点击领取、不绕过任何平台的风控或人机校验。领取动作普遍要求登录态与实名信息，各平台服务条款也普遍禁止自动化代领——本项目的定位是**情报**，不是代跑腿。有人问「能不能帮我领」，答复是给出直链与所需条件，让他自己点一下。

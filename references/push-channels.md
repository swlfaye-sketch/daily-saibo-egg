# 推送通道专章：八类通道的获取路径、限额与实测记录

本文件回答一个问题：**清单生成之后，怎么让它出现在手机上。**

技能自身只负责产出（Markdown ＋ HTML）。推送是可选的第二步，由 `scripts/push_report.py` 承担，八个通道各自独立、互不影响，配哪个推哪个。

---

## 一、通道选型（先看这张表）

| 通道 | 获取凭据的路径 | 是否需要注册 | 手机端 | 正文上限 | 适合场景 |
|---|---|---|---|---|---|
| **ntfy** | 自取一个主题名即可 | **不需要** | 装 ntfy 应用订阅同名主题 | 约 3900 字节 | **想立刻看到效果，零配置起步** |
| **邮件** | 邮箱后台开 SMTP 授权码 | 用已有邮箱 | 任意邮件客户端 | 无实际限制 | **要留存、要 HTML 排版**；一家都不依赖 |
| **Server酱** | `sct.ftqq.com` 扫码登录取 SendKey | 需微信扫码 | 微信服务号 | 约 30 KB | 微信收推送的最短路径 |
| **PushPlus** | `pushplus.plus` 微信登录取 token | 需微信登录 | 微信公众号 | 约 20 KB | 同上，另支持群组 topic |
| **企业微信群机器人** | 群设置 → 群机器人 → 添加 | 需企业微信 | 企业微信 | **约 3900 字节（最紧）** | 已在用企业微信的团队 |
| **钉钉群机器人** | 群设置 → 智能群助手 → 添加机器人 | 需钉钉 | 钉钉 | 约 18 KB | 已在用钉钉的团队 |
| **飞书群机器人** | 群设置 → 群机器人 → 添加 | 需飞书 | 飞书 | 约 18 KB | 已在用飞书的团队 |
| **Bark** | App Store 装 Bark，应用内显示 key | 不需要 | iOS | 约 1800 字节 | iOS 原生通知，免费自建服务端亦可 |

**选型建议**：先用 **ntfy**（零成本、零注册，五分钟内能收到第一条）验证整条链路，再按实际使用习惯补一个长期通道。不必八个全开——每多一个通道，就多一处凭据要维护。

## 二、各通道的配置要点

### ntfy（推荐作为第一条通道）

1. 想一个**不易撞名**的主题字符串，例如 `saibo-egg-你的名字-2026`；
2. 手机装 ntfy 应用（iOS／Android 均有），订阅同一主题；
3. 配置里填 `topic` 即可，`server` 默认 `https://ntfy.sh`。

主题名**相当于密码**——知道主题名的人就能收到你的推送，所以不要用 `test`、`daily` 这类常见词。（也可自建服务端，把 `server` 改成自己的地址。）

### 邮件

- 填的是**邮箱授权码**，不是登录密码。QQ 邮箱在「设置 → 账户 → POP3/SMTP服务」里开启并生成授权码；
- 端口 465 配 `"use_ssl": true`；端口 587 配 `"use_ssl": false`（脚本自动走 STARTTLS）；
- `to` 是数组，可填多个收件人；
- 报告生成时若同名 `.html` 存在，脚本会**自动把它作为 HTML 正文**附加，手机上排版更好看。

### 钉钉

两种安全设置，任选其一，别同时开错：

- **自定义关键词**：把关键词填进 `keyword`，脚本会自动把它补进推送标题；
- **加签**：把 `secret` 填上，脚本按官方算法（`timestamp + "\n" + secret` 做 HMAC-SHA256 后 base64）自动签名。

### 飞书

- 若机器人开了签名校验，填 `secret`。飞书的签名算法与钉钉不同——是**以 `timestamp + "\n" + secret` 为密钥、对空串做 HMAC-SHA256 再 base64**，脚本已按此实现；
- 开关键词过滤时，报错是 `19024`，不是签名错，别改错地方。

### 企业微信

- 正文上限最紧（4096 字节），长清单**必然被截断**。脚本会截断并附一行说明，不会让平台静默丢弃；
- 若清单较长，建议这条通道只推「今日摘要」而非全量清单。

### PushPlus

- `topic` 可选：填了就推给该群组下所有订阅者，不填只推给自己。

## 三、常见错误码速查（脚本已内置中文解释）

| 通道 | 错误码 | 含义与处置 |
|---|---|---|
| 钉钉 | `300001` | access_token 无效，重新复制 |
| 钉钉 | `300005` | access_token 不存在——**多半是复制时漏了尾部字符**，回群设置重取 |
| 钉钉 | `310000` | 安全设置不匹配：关键词没命中，或开了加签但没填 secret |
| 钉钉 | `130101` | 发得太频，每分钟限 20 条 |
| 飞书 | `19001` | webhook 无效或机器人已停用 |
| 飞书 | `19021` | 签名校验失败：检查 secret 与本机时间 |
| 飞书 | `19024` | 关键词未命中 |
| 企业微信 | `93000` | webhook key 无效 |
| 企业微信 | `45009` | 超过频率限制 |
| Server酱 | `40001` | SendKey 错误 |
| Server酱 | `43004` | 免费额度用尽，次日恢复 |
| PushPlus | `903` | token 无效 |
| PushPlus | `902` | 当日次数已用尽 |
| Bark | `404` | device key 不存在 |
| ntfy | `429` | 同主题发送过频 |
| ntfy | `413` | 消息体过大 |

**脚本的处理原则**：把错误码翻译成「下一步该做什么」，而不是原样甩一个数字。拿不准的码则保留平台原文，不臆造解释。

## 四、实测记录（2026-09-20）

### 链路连通性

七个 HTTPS 通道（钉钉／飞书／企业微信／Server酱／PushPlus／Bark／ntfy）用**明显无效的凭据**各发一次：

- 全部返回**明确的业务错误码**（如 `300005`／`19001`／`93000`／`903`），而非连接失败或超时；
- 判据：**能收到业务错误码，说明 TLS 握手、DNS、路由、API 端点全部正常**，只差一个真凭据。

### 邮件的 SMTP 握手

| 服务商 | 地址 | 端口 | 结果 |
|---|---|---|---|
| QQ 邮箱 | `smtp.qq.com` | 465 | 握手成功 |
| 163 邮箱 | `smtp.163.com` | 465 | 握手成功 |
| 腾讯企业邮 | `smtp.exmail.qq.com` | 465 | 握手成功 |
| Gmail | `smtp.gmail.com` | 465 | 握手成功 |
| Outlook | `smtp.office365.com` | 587 | 握手成功 |

五家全部可达，**国内邮箱与境外邮箱均无网络障碍**。选哪家取决于是否愿意为它单独申请授权码。

### 端到端实发

**ntfy 已完成真实投递**（无任何凭据、无注册），脚本返回「已推送」。这是八个通道里唯一**开箱即用**的一条，因此推荐作为首条验证通道。

## 五、三条纪律

1. **凭据只放本机文件。** `push_config.json` 含明文凭据，`.gitignore` 已将其排除；**永远不要把该文件提交到仓库或贴到公开场合**。脚本也不接受在命令行明文传凭据，避免落入 shell 历史。
2. **超长必须显式截断。** 企业微信等通道对超长内容会静默丢弃或报错。脚本按通道各自的上限截断，并附「超长已截断」说明——**宁可让使用者看到被截断的完整版，也不要让他以为今天没有额度**。
3. **推送失败不算当日任务失败。** 清单本身已经落盘，推送只是投递环节。脚本逐通道报告结果，一个通道失败不影响其余通道，也不影响已产出的文件。
